# 控制通道实现

`stella-control` 包含控制器和客户端共用的连接机制。规范字节仍由控制平面规范定义并由
`stella-proto` 编码。crate 提供 `RecordReader`、`RecordWriter`、拥有字段字节的
`MessageBuilder`，以及分配出站消息 ID、验证精确入站序列并追踪最多 256 个未完成关联的
连接状态。

读取器和写入器泛型化于 Tokio `AsyncRead` 和 `AsyncWrite`，可在拆分 TLS 流、TCP 测试流和
内存双工流上运行，而无需了解底层承载如何建立。控制器授权、令牌消耗、网络状态、证书
信任、TCP 连接策略和重连不属于该 crate。

四字节长度前缀读入栈存储。小于 32 字节控制头或大于 1,048,576 字节的长度会在分配消息
体前失败。解码消息拥有其记录字节；不会有借自 I/O 缓冲的切片跨越 `.await`。凭据构造器
会从 `Debug` 输出中脱敏。

每个方向从消息 ID 1 开始。只有完整消息可编码后发送才保留一个 ID；接收仅接受期望 ID，
并在完整结构验证成功后推进。零、缺口、重复、较小值和回绕都是致命连接错误。TLS 导出器
证明使用标签 `EXPORTER-Stella-Control-v1`，其转录由类型化固定大小输入构建，防止调用方
改变字段顺序或遗漏绑定。
