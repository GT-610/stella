# 密码学实现

`stella-crypto` 实现 ADR 0009 指定的 0.1 必选套件。每个域字符串、字节范围、nonce 和
生命周期规则均以协议规范为准。crate 使用维护中的库执行 Ed25519、X25519、SHA-256、
HKDF-SHA256、ChaCha20-Poly1305、操作系统随机数、秘密清零和常量时间比较；它不自行
实现曲线运算、哈希、HMAC、HKDF、ChaCha20 或 Poly1305。

身份签名密钥是不可克隆的自有秘密，可由操作系统 RNG 生成或从显式 32 字节种子包装器
恢复。秘密包装器会隐藏 `Debug` 输出，字节只通过显式命名的方法暴露，并在释放时清零。
控制器和节点身份使用未加密的 PKCS#8 DER；文件访问、原子创建和 Windows ACL 检查在
应用边界处理。节点和控制器 ID 由不同的规范域前缀和 Ed25519 公钥派生，并以常量时间
比较验证。

每次对等交换都会创建新的不可克隆 X25519 秘密，拒绝全零共享秘密，再用精确的转录哈希
派生两个方向的数据密钥、两个 nonce 前缀以及发起方和响应方确认密钥。方向保护器把
四字节 nonce 前缀和大端受保护包序列号组成 12 字节 nonce，拒绝序列号零。

接收方向使用以最高已认证序列号为基准的 1,024 位滑动位图。预检查不会改变状态，只有
认证成功后才提交重放状态，因此失败的标签不能推进最高序列号或标记窗口位置。错误值不
包含密钥、种子、明文、密文或标签字节。
