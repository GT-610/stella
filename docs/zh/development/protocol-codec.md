# 协议编解码器实现

`stella-common` 和 `stella-proto` 实现规范线上格式，但不把 Rust 内存布局变成协议的一
部分。`stella-common` 管理节点、控制器、网络和授权标识符、MAC 地址及十六进制显示与
解析。`stella-proto` 管理数据平面和控制平面头部、分片、保活、扩展、TLV、成员授权、
网络策略与对等握手结构的规范字节布局。

全部输入都不可信。解码器使用带边界检查的切片游标和显式大端整数读取，不将输入字节
转换为 Rust 结构体，也不会在已验证边界之外索引。成功解码必须消耗恰好提供的记录，
多余字节是错误。需要安全状态时，结构解码先验证魔数、版本、长度、标志和范围算术，
再由高层解析成员关系、密钥并认证字节。

编码器将精确长度写入调用方提供的有界存储，并先验证语义不变量。变长集合在计算编码
长度前检查协议限制，长度计算使用检查算术，保留和对齐字节始终显式置零。密码学调用方
负责原语操作；编解码器暴露关联数据和签名输入的准确字节范围。

所有公开编解码器都要有规范固定字节示例、最小和最大边界测试、字段级无效用例、精确
往返测试、不会 panic 的任意输入解码测试，以及编码/解码对称性和长度计算的属性测试。
协议文档保持权威地位，向量实现时发现的差异必须先修正规范或登记到勘误表。
