# 控制器实现

`stella-server` 是自托管授权方和控制平面端点。它不是单播数据的必经中继：经过认证的节点
获得签名授权、策略、对等身份和直连 UDP 端点，然后彼此交换数据。

进程包含三个边界。Tokio 运行时接受 TCP、完成 TLS 1.3，并为每个已认证连接运行一个有界
会话任务；专用阻塞授权线程以提交顺序拥有 redb 数据库并执行类型化命令；事件分发器把
已提交的授权变更转换为有界对等快照、增量、授权刷新和可用性变更。启动会验证配置、
控制器密钥、数据库绑定与不变量及 TLS 身份，随后才绑定 TCP。

控制器身份是受保护的 Ed25519 PKCS#8 DER，TLS 服务器密钥和证书独立保存。初始化是显式
事务而非启动副作用，不会覆盖已有身份或数据库。授权状态的所有变更在串行化的数据库
事务中完成，令牌只存储域分隔摘要，并随成功注册或加入操作原子消耗。

会话在身份、版本、大小、序列、关联和授权检查通过前都不可信。认证后，单个活动会话
循环有序处理加入、离开、端点发布、快照请求和心跳。它从原子授权视图构造签名授权、策略
和对等快照，避免将不同时刻的记录组合到同一响应中。连接失败、授权撤销或租约过期都会
撤销活动状态；日志和错误不会回显令牌、签名、密钥或攻击者提供的文本。
