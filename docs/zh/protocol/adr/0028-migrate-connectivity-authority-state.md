# ADR 0028：存储连接 generation 前迁移授权状态

- 状态：已接受
- 日期：2026-09-01

## 背景

0.2 控制器需要将成员最新的完整连接 generation 与稳定成员关系和 0.1 端点租约分别持久化。
redb schema 1 没有相应表。如果只增加表而不升级 schema，旧控制器仍能打开数据库，
却不会在退出、暂停、禁用或租约到期时清理连接记录，后续升级会看到违反 ADR 0027 的残留状态。
直接拒绝 schema 1 又会迫使现有部署丢弃或手动重建有效授权数据。

## 决策

`AuthorityStore::open` 使用单次 redb 写事务将 schema 1 升级为 2：创建空 `connectivity`
表并更新元数据，不重写既有节点、网络、成员、端点和令牌记录；事务失败保持旧库不变。

连接记录使用 `network_id || node_id` 键，值重复网络 ID 并包含经规范化验证的完整 0.2
连接记录。内部节点 ID 支持启动时发现键值不一致，无需把连接凭据解释为身份。

记录有效的前提是同键在线端点租约、已启用节点、现存网络和活动成员关系均存在。
发布 generation 在同一事务中创建或刷新在线租约；替换或撤销可见连接信息以及创建缺失租约
只推进一次快照 revision。相同内容发布只刷新租约。租约到期和授权清理原子删除两类记录；
若独立刷新后的在线租约仍有效，generation 到期只删除连接记录。

备份保留新表及 schema 2。旧二进制拒绝升级后的元数据，不能修改其不理解的状态。

## 影响

升级保留原有授权状态，并阻止不安全降级。迁移单向；运行旧版本须恢复升级前备份。
连接凭据在 generation 有效期内存在于数据库和备份中，诊断只暴露安全元数据，
拥有记录的内存缓冲区在释放时清零。
