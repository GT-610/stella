# ADR 0035：控制器重连期间保留有效转发

- 状态：已接受
- 日期：2026-09-02

## 背景

控制面规范允许控制器短暂故障期间继续使用已建立的对等数据会话，前提是其 grant、网络
epoch 和会话寿命仍然有效。ADR 0022 为首个 Windows 实现刻意选择了更小的状态机：TLS
控制会话一旦结束，就销毁完整数据运行时。

这一保守里程碑可以防止陈旧控制器状态跨进程重启存活，但也会把控制器重启、代理中断或
短暂 TLS 故障扩大为不必要的 L2 中断。即使数据面已经持有执行剩余有效期所需的全部授权
材料，健康的直连和 Relay 游戏流量仍会失去 TAP 设备与已认证对等会话。

## 决策

Windows 控制监督器跨多个独立控制器 TLS 会话持有数据运行时。意外控制故障和已认证的
`SERVER_SHUTDOWN` 只关闭当前控制连接。在等待重连退避、建立 TLS、认证和重放已配置
join 的过程中，监督器继续执行有界 TAP、直连 UDP、Relay、ICE、keepalive、握手、过期
清理和 Relay 恢复处理。

断开控制器期间只使用最后一次完整验证的内存网络视图。客户端不会持久化收到的 grant、
策略、对等记录、连接 generation 或 Relay 凭据，也不会延长任何控制器签发的有效期。
既有数据包、握手、grant、epoch 和会话验证仍是权威边界。缓存中的对端只能在相同签名
边界仍有效时保持、换钥或重新建立已认证会话；客户端不能发现或授权缓存视图中不存在的
对端。

新的连接完成认证并重新加入全部已配置网络后，监督器发布当前端点和连接状态，应用最新
Relay 配置，并用新的完整控制器视图协调保留的数据运行时。被移除或撤销的网络与对端会在
恢复正常多路控制处理前撤回。数据运行时操作失败仍会关闭该运行时，并只在获得新控制器
状态后创建替换；控制面故障不会关闭数据运行时。

既有全抖动重连上限继续生效。已认证关闭期限和已注册重试延迟是最短等待时间，不代表可
信任替换端点。离线期间发生的 Relay 连接变化保持锁存，并在下一次认证连接后发布。

本决策只取代 ADR 0022 中“每次控制会话故障都销毁转发状态”的要求；ADR 0022 关于
持久化、新鲜 join、顺序、correlation 和验证的要求保持不变。

## 影响

控制器维护以及短暂 TLS 或代理故障不再中断其他方面仍然有效的 L2 游戏流量。数据 I/O 与
维护会和每个等待及控制激活 future 一起参与选择，因此重连工作不能饿死数据处理。

控制器分区期间，被撤销对端只能在之前签发的密码学授权或会话过期前继续可达。这是协议
已经允许的有界陈旧授权窗口；任何状态都不会跨客户端重启存活，成功重连后会立即应用更新
的权威状态。
