# ADR 0032：限制 Relay DNS 准备时间

- 状态：已接受
- 日期：2026-09-02

## 背景

Relay 服务记录可以同时包含控制器提供的数值地址和规范主机名。Windows 客户端在应用
ADR 0031 的 carrier 建立预算前，先用操作系统 DNS 结果补充数值地址。

协议最多允许 8 个 Relay 服务。如果为每个服务串行执行各自 5 秒的解析期限，严格或故障
DNS 会在尝试任何 carrier 前把 Relay 回退额外延迟约 40 秒。该延迟随配置规模增长，处于
原本固定的回退上界之外。

## 决策

Windows 客户端并发启动所有必要的 Relay 主机名查询，并让完整的 Relay DNS 准备阶段
共享一个 5 秒单调时钟总期限。查询完成顺序不得改变控制器提供的服务顺序，也不得改变
后续 carrier 优先级。

成功的查询在协议限制内补充去重后的可用地址。查询失败或总期限耗尽时，只要服务记录中
存在数值地址，就继续使用这些地址。纯 DNS 服务会记录安全的解析错误或超时错误，并且不
产生候选。只由代理解析的 Secure WebSocket-only 服务不执行本地 DNS。

实现会共同轮询拥有所有权的解析 future，不启动游离任务，也不增加依赖。共享期限到达后
丢弃尚未完成的查询，从 Stella 一侧取消对应 future。解析器和新超时路径都不会收到或
记录凭据、Relay secret、代理响应及数据包内容。

## 影响

无论控制器下发 1 个还是 8 个服务，Relay 选择准备最多耗时 5 秒。结合 ADR 0031，客户端
到达 Secure WebSocket carrier 的时间由固定的准备期限和前置 carrier 预算决定，不再
与服务数量成正比。

并发查询会短暂占用最多 8 个操作系统解析操作，这已经是协议上限，相比串行阻塞启动更可
控。在本地 DNS 被过滤或不可用时，数值 Relay 地址仍是重要的可靠性保障。
