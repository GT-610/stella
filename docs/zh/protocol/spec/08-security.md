# 8. 安全

Stella 将控制器 TLS 身份、节点长期身份、成员授权、对等会话和数据包保护分为独立安全
上下文。TLS 1.3 建立控制通道后，双方以导出器绑定转录证明各自身份。控制器只在验证节点
公钥证明后评估注册或加入凭据。

对等数据会话使用签名的四消息 X25519 握手、双方临时密钥、网络 ID、epoch 和授权绑定。
HKDF 派生方向密钥、nonce 前缀和确认密钥；ChaCha20-Poly1305 提供认证和可选保密性。重放、
降级、错误端点、错误 epoch、过期授权和无效标签都必须失败关闭。会话按寿命、包计数或
授权状态变化换钥，旧会话只在有限接收窗口内保留。

## 参考实现的握手准入策略

验签或密钥协商之前，参考客户端只接纳控制器授权的 peer 端点，并按单调时钟应用令牌桶：
每 node 每秒 8 次、突发 32；每 endpoint 每秒 32 次、突发 64；每网络总计每秒 256 次、突发 256。
这些是本地实现默认值，不是线协议字段或协商常量。请求缓存响应的重传同样消耗预算；
超限静默丢弃。未知身份或端点不能创建限流状态，状态数量受授权 peer/path 集合约束并随其清理。

通过准入的 INIT 只认证一次，私有验证结果交给 responder 构造；不存在公开跳过认证的入口。
签名 stale-epoch 拒绝也须先验证所提交 grant 的控制器签名。

完整固定向量位于仓库 `protocol/vectors/session-v1.txt`，派生结果位于
`protocol/vectors/session-v1-keys.txt`，并附独立 Python 验证器。这些公开测试密钥 MUST NOT 用于部署。
